# UX: поиск App.list пересоздаёт активное поле и теряет фокус

## Summary

По статическому анализу общего списка каждый ввод запускает refresh → render → toolbar, который создаёт новый input и заменяет содержимое панели. Это угрожает непрерывному поиску во всех локальных/серверных списках. Исследование: docs/research/2026-11-05-ux-refactoring.md#n22. Код: src/titanium_platform/ui/list.js, toolbar/render/refresh. Фактический браузерный сценарий ещё нужно воспроизвести; замеров операторского времени нет.

## Steps to reproduce

1. Открыть экран с App.list и поиском (например, Выводы или карту цветов).
2. Ввести первый символ и дождаться обновления списка; не выбирать поле повторно.
3. Продолжить ввод нескольких символов, затем изменить текст в середине; проверить фокус и каретку.
4. Повторить на серверном списке с задержкой запроса, затем раскрыть/закрыть строку.

## Expected

Поиск остаётся тем же активным полем, фокус и каретка сохраняются; можно непрерывно ввести и отредактировать запрос. Обновление строк не прыгает по странице.

## Actual

В коде toolbar создаёт новый input, а App.fill(bar, parts) заменяет старый; render вызывается при refresh и раскрытии строки. Настоящее поведение фокуса/каретки пока не записано.

## Environment

Исходное дерево 3716444 / версия приложения 0.38.0, статическая сверка 2026-11-05. Браузер/Electron и вспомогательные технологии в этой задаче не запускались. Использовать тестовую мастерскую; данные оператора не изменять. P0 — порядок работ по research, severity medium — отдельная оценка дефекта.

## Acceptance criteria

- [ ] В настоящем браузере и Electron ввод нескольких символов и редактирование середины строки сохраняют фокус/каретку.
- [ ] Раскрытие/сворачивание строки и обновление результатов сохраняют видимую позицию.
- [ ] Поиск, фильтры со счётчиками, сортировка и порции 20 работают как раньше.
