# UX: модальные окна не удерживают фокус и выбирают опасное подтверждение

## Summary

Общий modal задаёт aria-modal и Escape, но не обрабатывает Tab/Shift+Tab и не делает фон inert; без полей начальный фокус получает последняя кнопка. В confirmBox последняя кнопка — действие удаления. Исследование #n38; src/titanium_platform/ui/dialogs.js modal/confirmBox. Это статическое подтверждение устройства, а не отчёт о выполненном удалении.

## Steps to reproduce

1. Открыть подтверждение удаления на безопасном тестовом объекте, не подтверждая удаление.
2. Проверить, какая кнопка получила фокус сразу после открытия.
3. Несколько раз нажать Tab и Shift+Tab и проверить возможность ухода на фон.
4. Закрыть Escape, затем повторить с обычной формой и проверить возврат фокуса.

## Expected

Tab цикличен внутри диалога; фон не интерактивен. Опасное подтверждение открывается с фокусом на «Отмена». Закрытие возвращает фокус инициатору, не выдавая закрытие за отмену фоновой операции.

## Actual

onKey обрабатывает только Escape; inert/focus trap отсутствуют. Начальный фокус выбирается как первый input либо buttons[buttons.length-1]; confirmBox ставит действие последним. Браузер и скринридер ещё не проверены.

## Environment

Исходное дерево 3716444 / версия приложения 0.38.0, статическая сверка 2026-11-05. Браузер/Electron и вспомогательные технологии в этой задаче не запускались. Использовать тестовую мастерскую; данные оператора не изменять. P0 — порядок работ по research, severity medium — отдельная оценка дефекта.

## Acceptance criteria

- [ ] Tab/Shift+Tab не выходят за окно, фон недоступен клавиатуре и указателю.
- [ ] При удалении изначально выбрана «Отмена»; Escape не выполняет действие.
- [ ] Фокус возвращается инициатору; вложенное/повторно открытое окно и выполняемая операция имеют ясное поведение.
