# UX: «Перейти к содержимому» конфликтует с hash-router

## Summary

Skip-ссылка index.html использует href=#main, а router.start запускает render на любой hashchange. parse трактует main как id экрана; незнакомый id заменяется experiments. Поэтому доступный переход может менять раздел вместо переноса фокуса. Источник: research #n46; ui/index.html:11 и ui/router.js parse/start/render. Следствие подтверждено связью кода; браузерное воспроизведение требуется до исправления.

## Steps to reproduce

1. Открыть не-экспериментальный маршрут с аргументом/query, например работу, и записать адрес.
2. Клавиатурой перейти к ссылке «Перейти к содержимому» и активировать Enter.
3. Проверить hash, текущий экран и document.activeElement.
4. Повторить из каталога и после обычного перехода между разделами.

## Expected

Skip переносит фокус в main без изменения route, id и query. Обычная навигация задаёт осмысленный фокус экрану, локальное обновление сохраняет фокус у элемента.

## Actual

#main попадает в hashchange, ROUTE_ID.main отсутствует, render выбирает experiments. Специального обработчика skip нет; работа пользовательского ввода и состояние экрана в реальном окне ещё не проверялись.

## Environment

Исходное дерево 3716444 / версия приложения 0.38.0, статическая сверка 2026-11-05. Браузер/Electron и вспомогательные технологии в этой задаче не запускались. Использовать тестовую мастерскую; данные оператора не изменять. P0 — порядок работ по research, severity medium — отдельная оценка дефекта.

## Acceptance criteria

- [ ] После skip маршрут, аргумент/query и документ неизменны, activeElement находится в main.
- [ ] Skip работает клавиатурой из любого раздела; назад/вперёд остаются корректными.
- [ ] Локальное обновление списка не уводит фокус в заголовок или другой раздел.
