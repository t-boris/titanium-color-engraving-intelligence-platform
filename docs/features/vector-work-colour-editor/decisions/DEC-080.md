## Context

REQ-048 criterion 1 says merging is "offered only for two or more areas connected through shared borders" and that areas touching only at a corner are refused with a translated message. In release 0.6.0 the button was enabled for any two or more selected areas and only the server refused a set that does not border itself. The screen had no way to know which areas border one another. Asked on 2026-10-19 whether the refusal is enough, the operator chose to disable the button.

## Alternatives

1. Keep the button enabled for two or more areas and rely on the translated refusal of the server

## Decision

The button "Слить в один контур" is enabled only while the selected areas, two or more, are connected through shared borders; otherwise it is disabled and a line under the selection says why (the areas must border one another, a touch at a corner is not a border). The screen learns which areas border one another from a new read-only operation, GET /api/vector/{id}/neighbours, that answers for the job's current split version with the same relation that merging uses (segment.neighbours); the screen asks once per split version. The server keeps refusing an unconnected or corner-only set with its translated message, so every other client is checked as before.

## Reason

The operator's answer; an offer the server will refuse is a click that cannot succeed. The neighbour relation is the one the merge uses, so the screen and the server cannot disagree.

## Consequences

Adds one read-only route and one cached request per split version (adjacency of every area, about 40 kB for 986 areas). It extends the API without changing any existing operation.
