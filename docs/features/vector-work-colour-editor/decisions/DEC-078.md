## Context

REQ-046 refuses "a merge with fewer than two colours" and plan I-5 says to reject insufficient selections. The editor screen already required two ticked layers, but the operation merge_titanium accepted one selected colour merged into a different target (entries=[A], into=B), because it counted the target as the second colour. Asked on 2026-10-19 which reading is binding, the operator chose the literal one.

## Alternatives

1. The target counts as one of the two colours, so one selected colour merged into another target stays valid (the API as built in 0.6.0)

## Decision

A merge of titanium colours is refused unless at least two distinct titanium colours that the colouring uses are selected. The target is any measured palette colour: one of the selected colours or another. Every selected colour except the target is merged away. The refusal is one translated message: "choose two or more titanium colours of the colouring to merge". A target outside the measured palette keeps its own refusal.

## Reason

The operator's answer; it is the literal reading of REQ-046 criterion 4 and of plan I-5, and it makes the operation agree with the screen, which has always asked for two ticked layers.

## Consequences

Narrows the operation's contract of release 0.6.0: a request with one selected colour was valid and is refused from release 0.6.1. The screen is unchanged.
