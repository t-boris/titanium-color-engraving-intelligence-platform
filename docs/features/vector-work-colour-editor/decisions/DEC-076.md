## Context

The operator chose all three meanings of "объединять цвета": two titanium colours into one, source colours into one group, neighbouring areas into one contour. The split is a planar map: regions are loops of shared arcs (segment.py), so geometry must stay gapless after any change.

## Alternatives

1. Merge source colours only as a colouring link without a new document version
2. Choose the next arc at a junction by angle

## Decision

(1) Titanium colours into one: every colour choice and area choice that resolves to a merged-away titanium colour becomes the target by hand, so the file has one layer fewer; automatic modes keep it. (2) Source colours into one: a new document version in which the chosen source colours are one palette entry (pixel-weighted mean Lab; the number of the member with most pixels, so the other numbers do not shift), their areas relabelled; choices of the merged-away colours are dropped. (3) Neighbouring areas into one contour: a new document version in which a connected set of areas (sharing borders, not only a corner) becomes one area: the arcs between them are dropped, the boundary is re-chained from the loops' own successor relation (exact at pinch points and holes), loops ordered outer first by signed area, arcs renumbered; the area keeps the id, source colour and choices of its largest member. The result stays gapless and loads in LightBurn.

## Reason

The operator's answers; working on the shared arcs keeps the picture gapless by construction, and stable colour numbers keep the operator's references valid.

## Consequences

Each geometric merge writes a new document version file (kept on disk, as every version is); a merged colour's number keeps a gap in the numbering.
