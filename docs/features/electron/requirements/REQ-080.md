## Statement

The system shall provide an installable, maintainable desktop workshop that preserves existing local workflows, works independently of cloud services and gives the user explicit control over networking and diagnostics.

## Acceptance Criteria

- [ ] The public desktop beta installs and launches on macOS on Apple Silicon and Windows x64 without manual installation of Python, pip, Node.js or terminal commands. Minimum supported OS versions are established through platform validation.
- [ ] Installers and verified updates are distributed from project-owner-controlled hosting using project-owner-controlled platform signing. Verification failures prevent installation; signing keys are excluded from the repository.
- [ ] The user can create a workshop or open an existing folder without an account. Existing ~/.titanium-platform data is offered for opening, the last selected workshop is remembered, and cancellation or permission errors leave no partially initialized workshop.
- [ ] Workshop data remains outside the application installation and survives updates. Updates occur only at a safe operation boundary.
- [ ] The application shows core startup, readiness and failure states, checks core compatibility and database availability before enabling operations, and prevents concurrent migration of the same workshop. Core failure offers restart and local diagnostics without an infinite restart loop.
- [ ] Application shutdown safely completes or cancels operations and releases processes, ports and workshop locks so that the workshop can reopen.
- [ ] With outgoing networking blocked and no cloud account, users can open workshops, load local photographs and RAW files, measure, use color maps, perform vector work and supported photo prediction, save and export LightBurn files. Downloaded laboratories remain usable offline. External AI actions are explicitly identified as network-dependent.
- [ ] Network actions follow explicitly selected functions and settings. Application and laboratory update checks are configurable; with automatic checks disabled, ordinary local work sends nothing to publication or catalogue services. File and usage telemetry is absent by default.
- [ ] Cloud, authentication and update failures do not block local work or discard confirmed local results. Errors provide localized explanations and recovery actions; interrupted uploads and stale caches are distinguishable from published releases and server-confirmed current data.
- [ ] Logs remain local and are not sent automatically. Diagnostic export requires an explicit action and removes secrets and private data. Clean-machine acceptance checks reproducibly verify the distributed installers on the supported platform matrix.
