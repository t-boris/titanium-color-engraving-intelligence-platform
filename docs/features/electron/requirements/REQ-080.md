## Statement

The system shall provide an installable, maintainable desktop workshop that preserves existing local workflows, works independently of cloud services and gives the user explicit control over networking and diagnostics.

## Acceptance Criteria

- [x] The internal desktop beta provides a bundled Python core and Electron shell for macOS Apple Silicon and Windows x64; packaged-core and shell smoke evidence is recorded. Clean-machine installation and minimum supported OS validation for the public beta are tracked in desktop-macos-windows / REQ-087.
- [x] Internal beta builds are distributed from project-owner-controlled GitHub pre-releases under DEC-044: macOS uses the owner's Developer ID without notarization, Windows builds are unsigned. Verified signed installers and updates for the public beta are tracked in desktop-macos-windows / REQ-088.
- [x] The user can create a workshop or open an existing folder without an account. Existing ~/.titanium-platform data is offered for opening, the last selected workshop is remembered, and cancellation or permission errors leave no partially initialized workshop.
- [x] Workshop data remains outside the application installation and survives manual internal-beta application replacement. Applying verified updates only at safe operation boundaries is tracked in desktop-macos-windows / REQ-089.
- [x] The application shows core startup, readiness and failure states, checks core compatibility and database availability before enabling operations, and prevents concurrent migration of the same workshop. Core failure offers restart and local diagnostics without an infinite restart loop.
- [x] Application shutdown safely completes or cancels operations and releases processes, ports and workshop locks so that the workshop can reopen.
- [x] With outgoing networking blocked and no cloud account, users can open workshops, load local photographs and RAW files, measure, use color maps, perform vector work and supported photo prediction, save and export LightBurn files. Downloaded laboratories remain usable offline. External AI actions are explicitly identified as network-dependent.
- [x] Network actions follow explicitly selected functions and settings. Application and laboratory update checks are configurable; with automatic checks disabled, ordinary local work sends nothing to publication or catalogue services. File and usage telemetry is absent by default.
- [x] Cloud, authentication and update failures do not block local work or discard confirmed local results. Errors provide localized explanations and recovery actions; interrupted uploads and stale caches are distinguishable from published releases and server-confirmed current data.
- [x] Logs remain local and are not sent automatically. Diagnostic export requires an explicit action and removes secrets and private data.
