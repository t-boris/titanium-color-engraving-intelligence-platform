## Statement

The system shall connect, retain, update and disconnect external laboratory releases safely while preserving source isolation, provenance and existing work. In the first online beta, laboratory owners shall create public and invitation-only private laboratories and publish releases. Readers shall browse public publications and download or connect public releases without registration. Author cloud actions shall require an account; access to invitation-only private laboratories and their releases shall require sign-in and server-side invitation authorization. File exchange shall work independently of registration. Local editing shall not modify another owner's publications. Participant contributions shall remain outside the first online beta.

## Acceptance Criteria

- [ ] In the first online beta, the laboratory owner creates public or invitation-only private laboratories and publishes their releases; participant contributions remain outside the first online beta.
- [ ] Readers can browse public publications and download or connect public releases without registration.
- [ ] Author cloud actions require an account. Access to invitation-only private laboratories and their releases requires sign-in and server-side invitation authorization before browsing, downloading or connecting.
- [x] File exchange works independently of registration.
- [x] Local editing cannot modify another owner's publications.
- [x] Before import confirmation, users see the declared author, laboratory, release, equipment, materials, contents and usage terms. Unverified file authorship is identified explicitly.
- [x] Import incrementally validates compatibility, resource limits, finite numbers, identifier uniqueness, references and content integrity, with visible progress and cancellation.
- [x] A complete validated release becomes available atomically. Malformed or truncated input, integrity failures, limit violations, cancellation, interruption and insufficient disk space leave existing sources and own observations unchanged. Large-library verification records elapsed time, peak memory, temporary disk use and cancellation behavior on documented hardware.
- [x] Repeated import of the same release identity and hash adds nothing; the same release identity with different content is rejected. Observation provenance remains stable across imports and updates.
- [x] Connected releases are separate, read-only local sources, remain available after restart and without the author's files, and show identity, version, retrieval date, authorship verification and compatibility state.
- [ ] Users can connect public releases without an account. Losing online access does not erase downloaded snapshots or invalidate saved work.
- [x] Update checks are manual or explicitly configured and show added, changed and withdrawn results. A new release is activated only after complete download and validation and never overwrites a previous snapshot.
- [x] Saved work stays pinned until the user explicitly updates its source. The application previews affected colors, recipes and unusable assignments; confirmation creates a new work version with a route back to the previous one.
- [x] Owner withdrawals preserve immutable release content and record a reason or replacement. Once learned, withdrawal excludes a result from new automatic selection, labels manual use and warns affected saved work. Offline status is never represented as confirmation that withdrawal information is current.
- [x] Disconnecting stops update checks and hides the source from ordinary selection for new work. Before removal, affected saved work is shown; referenced snapshots remain available until references are removed or work data is safely transferred. Removing unused cache changes no own observations and reports no local work to the author.
