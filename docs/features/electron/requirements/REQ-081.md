## Statement

The system shall provide complete, consistent workshop backup and restoration and require recoverable, compatibility-checked local data migrations.

## Acceptance Criteria

- [ ] A full backup contains a consistent database snapshot, including committed WAL data, and every user file required to reopen saved work and measurements. A portable laboratory release is explicitly distinguished from a full backup.
- [ ] Restoring into a different folder preserves access to saved work and its source files. Overwriting the current workshop requires a separate explicit choice.
- [ ] Insufficient space, unreadable files or interruption cannot mark an incomplete backup as successful or replace the last successful backup.
- [ ] Before schema migration, the application checks compatibility, available space and successful creation of a consistent recovery backup.
- [ ] Failed or interrupted migration leaves either the original workshop or a recoverable consistent snapshot available to the previous compatible application; partially migrated working data is never activated.
- [ ] Unknown newer schemas are rejected with an explanation or opened only in a supported read-only mode. Older code is never started automatically against an incompatible schema.
- [ ] Recovery and rollback are documented and verified, including coordinated restoration of database and files when required.
