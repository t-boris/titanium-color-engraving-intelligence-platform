## Statement

The system shall export selected own results as a portable, privacy-preserving numerical laboratory release with explicit usage terms, reproducible statistics and a safe, versioned compatibility contract.

## Acceptance Criteria

- [ ] Before file export or online publication, the owner reviews selected own measurements and profiles, excluded fields and usage terms selected from an approved list. Connected external data cannot be republished in v1; own transfer experiments remain eligible with their original provenance.
- [ ] A release uses a versioned public contract independent of the internal database and includes sufficient numerical data for supported calculations, stable laboratory, release and observation identities, release version, provenance, content hash, versioned usage terms and relevant schema and algorithm versions.
- [ ] Only allowlisted fields are exported, and the resulting release is validated. RAW files, photographs, image payloads and previews, LightBurn geometry, spatial masks and working documents are excluded. Local paths, original filenames, private notes, AI conversations, credentials, email addresses and serial numbers are excluded; public descriptions are entered separately.
- [ ] A fixture containing unique markers in private fields and image bytes confirms that none appears in exported files or actual publication requests.
- [ ] Published summaries, counts, colors and quality metrics are calculated solely from the selected observations. Multiple photographs or layers of one engraving and repeated imports do not count as independent engravings. Missing repeatability estimates remain explicitly unavailable.
- [ ] Measurement bases and quality states are preserved. Incompatible physical setups and measurement bases are not averaged merely because equipment names match. With identical selected data and algorithm versions, transferred Lab values and curve points agree within 1e-6.
- [ ] Export handles validated large libraries incrementally. A benchmark-backed resource policy defines supported input sizes, record counts, profile dimensions, nesting, memory and temporary disk consumption; evidence records dataset sizes, hardware, elapsed time, peak memory and output size.
- [ ] External releases execute no supplied code and fetch no referenced resources. Unsafe protocols and external paths are rejected. Limit violations cause explicit failure without truncation, partial activation, secret disclosure or preventing the workshop from reopening.
- [ ] Unsupported major formats are rejected before activation with a compatibility explanation. A documented minor-version and capability policy prevents unsupported profiles from being silently treated as usable. Published observations remain unchanged by derived-value recalculation, and supported older fixtures preserve results and provenance after application updates.
