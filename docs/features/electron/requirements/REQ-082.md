## Statement

The system shall isolate the desktop interface and local service and provide optional, protected LAN access through persistent, owner-managed device authorization.

## Acceptance Criteria

- [ ] Normal startup exposes the local service only on loopback. The desktop interface has restricted privileges and exposes only explicitly permitted privileged operations.
- [ ] The local API authenticates trusted application sessions and protects browser requests against unauthorized origins and request forgery. An unrelated web page cannot read or modify the workshop.
- [ ] LAN access requires explicit owner activation and device pairing over protected transport. A paired tablet can open the interface and upload a photograph.
- [ ] Trusted-device authorization survives application and tablet restarts while LAN access is enabled. The owner can inspect and revoke devices; revocation terminates active access and prevents reconnection until pairing is repeated.
- [ ] Unpaired devices cannot access workshop data, and tablet authorization does not disclose the desktop session secret.
- [ ] Disabling LAN access closes external access without interrupting desktop work. Pairing and firewall behavior are verified on both supported platforms.
- [ ] Imported and cloud-provided text is rendered as data: malicious HTML or JavaScript does not execute. Session secrets and sensitive data are excluded from interface logs and laboratory releases.
