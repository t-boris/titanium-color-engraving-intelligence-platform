# Локальное приложение Electron и обмен лабораториями

## Idea

Полноценное настольное приложение «Лазерная мастерская» для macOS и Windows с локальными данными и вычислениями и необязательным обменом числовыми результатами через опубликованные лаборатории. Пользователь устанавливает приложение без Python и терминала, работает со своими RAW, фотографиями и LightBurn-файлами на своём компьютере, а при желании публикует выбранные измерения без исходных изображений. Другой мастер подключает версию лаборатории и использует её палитру и тональные профили для локального предпросмотра своих изображений. Сначала реализуется переносимый файл лаборатории, затем оболочка Electron и облачный каталог.

## Статус и происхождение

Это подробное предложение к разработке по обсуждению с владельцем проекта 21 октября 2026 года. Пользователь выбрал направление: локальное приложение, Electron, macOS/Windows, публикация результатов без исходных изображений, подключение чужих лабораторий. Требования остаются draft до продуктового ревью с учётом принятых решений: переносимый формат .tcelab v1, первая desktop-бета для macOS Apple Silicon и Windows x64, выбор автором условий использования из утверждённого списка, публичные и закрытые лаборатории с приглашениями и серверной авторизацией читателей. Минимальные версии ОС, состав списка условий использования и остальные нерешённые детали требуют согласования. В рамках подготовки этой фичи код приложения, рабочая база и настройки облака не изменяются.

## Проблема и ожидаемый результат

Существующая мастерская требует Python-окружения, запуска сервера и браузера. Это затрудняет установку у других мастеров. Полная облачная версия потребовала бы загрузки крупных RAW, серверных вычислений и переноса всей приватной мастерской. Обмен числовыми результатами позволяет распространять накопленные знания без этих требований.

Результат: мастер устанавливает обычное приложение, сохраняет контроль над исходниками, работает без облачного аккаунта и выбирает, какие результаты публиковать. Его опубликованная лаборатория доступна другим даже при выключенном компьютере автора. Загруженный набор работает офлайн. Для чужого оборудования набор является исходной гипотезой и палитрой автора; фактическое воспроизведение подтверждается собственным экспериментом.

### Цели

- Установка и обновление без ручной установки Python, pip, Node.js и терминальных команд.
- Сохранение текущих сценариев измерения, цветовой карты, векторных работ, фотопрогноза и экспорта LightBurn.
- Перенос числовой лаборатории файлом между компьютерами до появления сервера.
- Явная публикация ограниченного набора данных; отсутствие автоматической выгрузки рабочей SQLite.
- Подписка на опубликованные версии с воспроизводимыми палитрами и прогнозами.
- Повторное использование Python-ядра и существующего JavaScript-интерфейса.
- Малый облачный сервис с базой данных; серверная обработка RAW и хранилище пользовательских исходников не нужны.

### За пределами первого выпуска

Полная синхронизация мастерской между устройствами; облачный архив RAW; совместное редактирование одного проекта; прямое управление лазером; автоматический перенос калибровки между физическими лазерами; облачное обучение на всех чужих результатах; биллинг; маркетплейс; мобильное приложение. Linux остаётся последующим направлением после проверки macOS и Windows. Внешние AI-функции сохраняют существующие требования к сети и ключам и не объявляются офлайн.

## Термины и границы доверия

| Сущность | Назначение и источник истины |
|---|---|
| Локальная лаборатория | Полная рабочая мастерская на диске владельца: SQLite, исходники, измерения, планы и история. Не требует облачной регистрации |
| Публикация | Выбранная владельцем проекция измерений и профилей, подготовленная по отдельной схеме с разрешённым списком полей |
| Выпуск лаборатории | Неизменяемый снимок публикации с UUID лаборатории, номером версии, хешем содержимого и версиями схемы/алгоритмов |
| Подключённая лаборатория | Локально сохранённый выпуск внешнего источника, доступный только для чтения и отделённый от собственных измерений |
| Подписка | Связь с облачной лабораторией для проверки новых выпусков; не разрешает серверу менять сохранённые работы |
| Проверка переноса | Новый собственный эксперимент на другом оборудовании со ссылкой на исходную публикацию |
| Полная резервная копия | SQLite и необходимые пользовательские файлы. Публикация её не заменяет |

Внешние измерения идентифицируются как (origin_lab_id, measurement_id). Локальные числовые id SQLite не являются глобальными идентификаторами. Копирование набора и повторное подключение не создаёт независимых повторов. Разные физические лазеры и разные способы измерения не становятся одной статистической выборкой из-за похожих названий оборудования.

## Основные пользовательские сценарии

### 1. Первый запуск и существующие данные

Пользователь устанавливает приложение, выбирает «Начать локально» или «Открыть существующую мастерскую». При наличии ~/.titanium-platform приложение предлагает использовать её, показывает расположение и не создаёт вторую пустую мастерскую без объяснения. Данные лежат вне каталога программы и не удаляются обычным обновлением. Повторный запуск открывает выбранную мастерскую. Перед изменением схемы создаётся согласованная резервная копия; несовместимая база не открывается на запись.

### 2. Обычная офлайн-работа

Приложение запускает собственный Python-процесс, показывает готовность и состояние обработки. RAW, исходные изображения и LightBurn остаются локально. Локальные вычисления и экспорт работают при заблокированной сети. Облачный вход и предложения публикации не прерывают работу. Экспорт остаётся файлом LightBurn, оператор запускает гравировку в LightBurn.

### 3. Перенос без облака

Владелец выбирает оборудование, материал и результаты; видит состав и исключённые поля; сохраняет файл .tcelab. Получатель открывает файл, видит автора как заявленные метаданные, параметры установки, состав, ограничения и версию. После подтверждения импорт атомарно создаёт подключённый источник. Исходная база, фотографии и собственные наблюдения получателя не изменяются.

### 4. Использование чужой палитры

В работе можно выбрать «Мои измерения» или конкретный выпуск подключённой лаборатории. Векторная раскраска использует палитру выбранного источника. Фотопрогноз использует только подходящие числовые профили того же режима и условий; там, где данных недостаточно, сохраняются существующие отказы и обозначение непредсказанных пикселей. Исходное изображение получателя обрабатывается локально и не отправляется автору или серверу.

### 5. Публикация

Владелец входит в облачный аккаунт для публикации, создаёт онлайн-лабораторию и подтверждает подготовленный состав. Публичный просмотр не требует регистрации; доступ читателя к закрытой лаборатории требует входа, приглашения и серверной проверки прав. Сервер проверяет авторство и схему, сохраняет целый выпуск и только после успешной фиксации делает его видимым. Повтор запроса после обрыва не создаёт дубликат. Публикация не даёт серверу доступ к диску автора.

### 6. Подключение и обновление

Пользователь просматривает публичную лабораторию на сайте и скачивает .tcelab или подключает её из приложения. В каталоге видны дата, версия, оборудование, материалы, число измерений и признаки качества. Новый выпуск сначала скачивается и проверяется, затем становится доступен для новых работ. Уже сохранённая работа продолжает ссылаться на прежний выпуск; обновление источника в ней — отдельная операция с предпросмотром изменений.

### 7. Отзыв результата и воспроизведение

Автор обнаружил ошибку: публикует новый выпуск с явным отзывом или заменой измерений и причиной. Новые работы не выбирают отозванные результаты автоматически; старые работы сохраняют происхождение и получают предупреждение при получении информации об отзыве. Скачанные пользователем данные невозможно гарантированно удалить дистанционно. Получатель может создать собственный тест по чужому рецепту; результат теста принадлежит его установке и не повышает статистику повторяемости исходного лазера.

Тексты интерфейса следуют существующей локализации. Значения цвета сопровождаются числовыми Lab и указанием измерительной основы; экранный sRGB является отображением цвета. Удаление подключённого набора не должно ломать сохранённые работы: используемые выпуски сохраняются, пока есть ссылки.

## Предлагаемая архитектура

```mermaid
flowchart TD
    E["Electron: окно, файлы, обновления"] --> P["Локальный Python / FastAPI"]
    P --> L["SQLite + исходники на диске"]
    P --> C["Кэш подключённых выпусков"]
    P -->|"Выбранные числовые данные по HTTPS"| A["API публикаций"]
    A --> N["Neon PostgreSQL"]
    W["Сайт: каталог и карточки"] --> A
    O["Приложение другого мастера"] --> A
```

Electron включает существующий UI; main-процесс запускает упакованный Python-backend, ожидает handshake версии/готовности, открывает окно и контролирует завершение. Backend выбирает свободный loopback-порт и получает секрет текущего сеанса; порт не является механизмом авторизации. Renderer работает без Node.js integration, с contextIsolation и sandbox; привилегированные действия доступны через ограниченный preload API. Содержимое публикации считается данными, не исполняемым HTML или кодом.

Отдельный адаптер EvidenceSource получает нормализованные измерения и профили из LocalEvidenceSource или PublishedEvidenceSource. Чистые вычисления палитры и прогноза не должны требовать исходных файлов автора. Сейчас colormap и prediction_store связаны с pair, SQLite-id и местами с LightBurn-файлами; нужен целевой рефакторинг, а не импорт фиктивных pair и не копия всей базы.

Файлы кэша и таблицы подключений отделены от таблицы собственных observation. Публикация вычисляет служебные признаки локально: исходное имя файла и путь для их восстановления не нужны. Для расчётов из одного набора выбирается совместимая установка и материал; автоматического смешивания нескольких лабораторий в первом выпуске нет.

Внешний API можно разместить на Vercel, записи и небольшие снимки — в Neon. Desktop не содержит общего пароля к Neon и обращается только к API. Нативный Python и его библиотеки не переносятся в облако. Объектное хранилище пользовательских фотографий не входит в архитектуру; файлы установщиков и резервные копии рассматриваются отдельно.

## Формат данных и облачный API

Переносимый .tcelab: UTF-8 JSON со строгой схемой, UUID, числовыми измерениями, тональными профилями, происхождением, условиями использования и SHA-256. Состав проходит проверку приватности; статистика пересчитывается по выбранным наблюдениям. Импорт атомарный. Облачный сервис хранит публичные и закрытые лаборатории и неизменяемые выпуски: публичное чтение без регистрации, доступ к закрытым лабораториям по приглашениям с аутентификацией и серверной авторизацией читателей, публикация владельцем через API, загрузка чанками и finalize. Полный контракт и API описываются отдельными DEC этой фичи.

## Надёжность, приватность и границы офлайн-режима

- Нет сети и нет аккаунта: локальные данные и уже загруженные наборы работают; публикация/проверка обновлений показывают недоступность и допускают повтор.
- Обрыв импорта: временный staging удаляется, прежний набор остаётся рабочим.
- Обрыв публикации: сервер не показывает частичный выпуск; повтор не создаёт вторую публикацию.
- Обрыв обновления: действующий выпуск и активные работы не меняются.
- Сбой backend: понятная ошибка, путь к локальным логам, безопасный перезапуск; без потери последних подтверждённых данных.
- Два экземпляра приложения: не запускают конкурирующие миграции одной базы; второй переключается на уже открытый экземпляр.
- Нет места на диске или нет прав: операция завершается до переключения источника, прежние данные доступны.
- Отзыв облачного доступа не уничтожает ранее полученные данные и не считается гарантией их удаления.
- Локальная диагностика не отправляется автоматически. Аналитика пользовательских файлов и телеметрия использования по умолчанию отсутствуют.
- Внешний AI — отдельное явно сетевое действие, ключ хранится локально вне публикуемого набора.
- Автопроверка облачных обновлений включается настройкой; полная локальная работа не зависит от update-сервера.
- Доступ с планшета в LAN сохраняется отдельным явно включаемым режимом с сопряжением; desktop-backend по умолчанию слушает только loopback.

## Совместимость с существующим проектом

Опорный контракт: [REQ-043](../titanium-color-engraving-intelligence-platform/requirements/REQ-043.md), стек [DEC-020](../titanium-color-engraving-intelligence-platform/decisions/DEC-020.md). Новая фича сохраняет офлайн-работу, неизменяемость измерений, ограничения LightBurn и отсутствие прямого управления лазером. Переход от одного Python-процесса к Electron + управляемому backend требует явно согласованного уточнения существующего контракта до реализации; старые требования здесь не редактируются и не объявляются отменёнными.

Затрагиваемые модули: cli, api/app, db, model, colormap, palette, prediction_store, vector_job и UI. Упаковка проверяет rawpy/OpenCV, numpy/scipy/sklearn и ONNX-ресурс. Незавершённые изменения рабочего дерева сохраняются отдельно от этой фичи.

## Предложение разработки

План является предложением последовательных небольших изменений. Разработка приложения не начинается созданием этой спецификации.

Суммарно 29–47 рабочих дней одного опытного разработчика, ориентировочно 6–10 недель, при последовательном выполнении. Это оценка, не срок обязательства: нативные зависимости, сертификаты и доступ к реальным Windows/macOS могут изменить календарь. Первый полезный инкремент D1+D2 доступен до облака и до окончательной упаковки. Разработку вести в соответствии с актуальными правилами CLAUDE.md; действующее отключение CI не менять без отдельного поручения. Сборки и тесты целевых ОС сначала организуются вручную/на доступных runners, без автоматического включения выключенного workflow.

Пакеты DEV-01…DEV-11 описываются в решении о последовательности разработки этой фичи.

## Стратегия проверки и критерий готовности

Основной end-to-end: автор на компьютере A создаёт или выбирает измерения → экспортирует числовой набор → компьютер B без каталогов автора импортирует его → строит палитру и фотопрогноз на собственном изображении → сохраняет работу → автор публикует новый выпуск → старая работа воспроизводится по старому, новая может выбрать новый → источник отзывается → предупреждение появляется без повреждения локальной работы.

Дополнительные обязательные проверки:
- Уникальные маркеры пути, имени файла, серийного номера, приватной заметки, email, токена и байтов изображения отсутствуют в экспортированном UTF-8 и HTTP-передаче.
- Палитра и кривые численно совпадают с локальным источником на одном и том же выбранном наборе; сравнивается Lab до 1e-6, без требования побитного совпадения между разными версиями вычислительных библиотек.
- Повторное фото одной гравировки, несколько слоёв и повторный импорт не повышают число независимых гравировок.
- Неподходящий режим, иной материал, неизвестная линза и точка вне диапазона не превращаются в безусловный прогноз.
- Плохой хеш, неизвестная major-схема, чужие ссылки, NaN/Infinity, превышение лимита, XSS-строки и исполняемые объекты отклоняются без частичного изменения.
- Два аккаунта не могут изменять лаборатории друг друга; запросы читают только опубликованные целые выпуски.
- Отсутствие сети, ошибка обновления и потеря учётной сессии не блокируют локальную работу.
- Установка/запуск/обновление и восстановление проверены на чистой macOS Apple Silicon и Windows x64; Intel Mac и Linux включаются только по подтверждённой матрице.
- После удаления/перемещения папки установленной программы данные мастерской остаются доступны; обновление с несовместимой схемой не делает автоматический откат к старому коду поверх новой базы.

Предлагаемая производительность для измерения на D0: импорт набора из 10 000 измерений не блокирует окно; прогресс виден не реже раза в секунду; базовый target до 10 секунд на согласованной тестовой машине с SSD. Характеристики машины и окончательный SLA фиксируются до утверждения performance-требований.

## Риски и открытые решения

Риски: нативная упаковка, зависимости от файлов автора, неполные условия измерения, неверные счётчики повторов, приватные поля, несовместимость версий и перенос цвета между лазерами.

Открытые вопросы регистрируются отдельными Q с рекомендованными ответами. Для старта D0/D1 они не мешают; до публичной беты должны быть согласованы минимальные версии ОС для macOS Apple Silicon и Windows x64, утверждённый список условий использования данных и разрешения каждого варианта, поддержка повторного экспорта и публикации импортированных данных и ограничения публикаций. Первая онлайн-бета поддерживает публичные и закрытые лаборатории; закрытые требуют приглашений и серверной авторизации читателей.
