## Context

The code counted tonal-curve engravings by photograph (`prediction._engraving_of` used pair_id), while the palette and the colour map count by engraving_id. REQ-083 forbids counting re-photographs of one engraving as independent, and its 1e-6 parity between own and published calculation needs one rule for both.

## Alternatives

1. Count by engraving but keep the curve's Lab averaging as it is (a re-photographed engraving weighs double in Lab)
2. Keep local counting by photograph and count by engraving only in releases (breaks parity)

## Decision

Tonal curves use engraving identity everywhere: re-photographs of one engraving are first averaged into one point per power, then the curve is built; engraving counts, spread, scale confirmation and size grouping count engravings. The prediction algorithm version is raised.

## Reason

The owner chose "by engraving, Lab too" on 2026-10-24.

## Consequences

Local numbers change where tonal engravings were re-photographed (spread, confirmation, scale size choice and slightly the curve Lab). A regression test records the changed values. Works pinned to an older algorithm version keep their confirmed result (REQ-085).
