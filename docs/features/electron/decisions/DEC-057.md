## Context

DEC-046 keeps both run modes: the console command serving the operator's browser on 127.0.0.1:8765 and the desktop shell running the same package as a hidden loopback child. REQ-080 asks that an unrelated web page open in the operator's browser cannot read or change the workshop (DNS rebinding, cross-site form posts) and that, under the shell, a browser on the same computer cannot use the shell's workshop. Image and download addresses in the UI are plain URLs, so a bearer token held in JavaScript would break them.

## Alternatives

1. CORS headers only: they do not stop a cross-site form post or a no-cors request, and do nothing against a page that rebinds its name to 127.0.0.1.
2. A bearer token added by the UI's fetch wrapper: every img, a and download address would need the token in its query string, where it is logged and copied.
3. No guard in browser mode, the guard under the shell only: the 8765 deployment is the operator's daily use and faces the same pages.

## Decision

api/security.py is an ASGI middleware in front of every route in both modes. Every request's Host must name this computer: a loopback name, an IP address, or a host listed in TCE_ALLOWED_HOSTS (the tests use testserver); anything else is refused with 421. A request that changes something (POST, PUT, PATCH, DELETE) whose Origin names another host, or that a browser marks Sec-Fetch-Site: cross-site, is refused with 403; a request without Origin (not a browser, or same-origin) passes. A body whose Content-Length is above the largest upload the application reads (601 MB) is refused with 413 before it is read. Under the desktop shell (titanium-platform --desktop, which requires TCE_SESSION_SECRET and binds 127.0.0.1 only) the shell opens its window once at /session/<secret>; that address, with the right secret and not yet spent, answers 303 to / and sets the cookie tce_session (HttpOnly, SameSite=Strict, a random value per launch); every other request without that cookie is refused with 403 «open the workshop from the application». The secret and the cookie value live only in the shell's and the core's memory for one launch; the core never writes them. A paired tablet on the LAN (DEC-047) gets its own device cookie on the LAN server and never the desktop session.

## Reason

The Host check defeats rebinding, the Origin and Sec-Fetch-Site checks defeat cross-site writes without touching the UI's plain URLs, the body limit stops an upload from filling memory before a route sees it, and a one-time bootstrap address plus an HttpOnly cookie gives the shell's window exclusive use of its core while images and downloads keep working as ordinary URLs.

## Consequences

tests/test_api_security.py covers each refusal and the one-time session address; a reverse proxy or another host name in front of the console mode needs TCE_ALLOWED_HOSTS; the LAN server (REQ-082) adds its own device cookie check beside this guard rather than reusing the desktop session.
