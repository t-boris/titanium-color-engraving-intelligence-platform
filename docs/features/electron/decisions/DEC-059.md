## Context

DEC-047 settled the transport (the workshop's own CA, a pairing code, a long-lived device token in a Secure HttpOnly cookie) and DEC-033 that LAN access is a separate mode switched on by the owner. Building it (lan.py, routes_lan.py, security.py) left choices DEC-047 does not make: when the second server starts, the cookie's SameSite value, the certificate's names, and which parts of the application a paired tablet may use.

## Alternatives

1. Start the LAN server from a cli.py flag: the desktop shell would need the flag too and a change of the setting would need a restart; the application's lifespan sees the setting in both run modes.
2. SameSite=Strict on the device cookie as on the desktop session: a tablet opening the workshop from a bookmark or a link would arrive without the cookie and land on the pairing page every time.
3. Let a paired tablet reach everything the owner's browser reaches: the backup, restore, network and pairing screens change the workshop's own computer and belong to the owner at it.

## Decision

The LAN server is a second uvicorn server with TLS inside the same process, started by the application's lifespan when the setting lan.enabled is on and started or stopped at runtime by PUT /api/lan without touching the loopback server; it binds 0.0.0.0 (TCE_LAN_BIND overrides it) on lan.port, 8766 by default, and a port already taken is reported as an error with LAN left off. The workshop CA is an EC P-256 key valid ten years under lan/ with the key at mode 0600; the server certificate (820 days) names localhost, 127.0.0.1, the host name, host.local and every IPv4 address of this computer, and is remade when the names change or within 30 days of expiry; the CA's SHA-256 fingerprint and the CA file (.crt) are shown on the «Сеть» screen and on the tablet's /pair page. A pairing code has six digits, lives 300 seconds, is spent by one use and cancelled after five wrong tries. Pairing answers with the cookie tce_device: a random token whose SHA-256 alone is stored in the device table (name, created, last seen, revoked), Secure, HttpOnly, SameSite=Lax; revocation is checked on every request and ends access at once. A request through the LAN server (marked by lan.Entry) without a valid device cookie may reach only /pair, /api/lan/pair and /api/lan/ca, and a page request is sent to /pair; the desktop session address /session/ is never served from the network; /api/lan, /api/network and /api/workshop (pairing, network settings, backups and restore) answer only the owner's own computer even to a paired device. The network settings (AI researcher, Google Fonts, update checks; the last off by default) are the setting network, applied as switches in research.py and fonts.py and read by the shell before an update check.

## Reason

Starting from the lifespan serves both run modes with one code path and lets the owner switch LAN on and off without a restart; Lax keeps the tablet's ordinary navigation signed in while a cross-site form post from another origin still fails the guard's Origin check; keeping the screens that change the computer owner-only follows DEC-033's principle that the tablet is a measuring device, not a second administrator.

## Consequences

tests/test_lan.py covers the certificate chain, the codes, the token hashing, revocation on the next request, the tablet upload path, the real TLS start and stop and the owner-only refusals; firewall behaviour and pairing on a real Windows machine remain to be checked by the owner (REQ-082 c6); the desktop shell's update check reads network.update_checks from the core before asking GitHub.
