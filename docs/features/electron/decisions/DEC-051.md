## Context

DEC-025 asks for an EvidenceSource with a local and a published adapter. The colour map, the palettes and the tonal curves are large pieces of code written against the workshop's tables; a second code path for published records would be a second source of errors and would break the 1e-6 parity REQ-083 demands.

## Alternatives

1. A published adapter that re-implements gathering for release records (the plan's first shape): two code paths to keep equal.
2. Importing release records into the workshop's own tables: they would mix with own measurements, against DEC-025 and REQ-085.
3. Reading the .tcelab file on every use: no indices, slow, and withdrawals would have to be applied in memory.

## Decision

Connecting a release builds, under labs/<release_id>/, a SQLite store with the application's own schema (laser_device, lens, material_profile, pair, observation, the row lengths and cleaning layers as derived values) filled from the release's records, plus a release_record table that maps every release UUID to its local id and kind. The palette, colour-map and prediction code then reads a connected release through the same functions as the workshop, with the snapshot store in place of the workshop's. Local ids are stable across releases of one laboratory: laser, lens and material ids are taken from the UUID (the first 13 hex digits), a photograph's id is its capture seq + 1, an observation's id its measurement seq + 1, and a palette entry's id is the SHA-256 of its group (parameters key, setup, titanium). The snapshot is opened read-only (query_only); records withdrawn by the laboratory are hidden by a temporary view over the observation table, so the snapshot itself never changes and a work's pin can keep its own list of hidden records. A snapshot whose layout version (lab_snapshot.VERSION) differs from the application's is rebuilt from the kept .tcelab file when it is next opened.

## Reason

One code path keeps the parity exact by construction and every later change to the algorithms applies to connected releases at once; stable ids keep a work's pinned laser, lens, titanium and palette colours meaningful across releases of the same laboratory; the overlay applies withdrawals without touching the snapshot.

## Consequences

lab_snapshot.py builds and opens snapshots; the parity test compares the workshop and its connected release within 1e-6 with the author's files blocked. A snapshot is about 12 times the file (SNAPSHOT_FACTOR) and is checked against free disk space before building.
