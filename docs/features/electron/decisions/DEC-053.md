## Context

REQ-085 asks that saved work retain the laboratory and release identities, the content hash, the selected recipes, the algorithm version and the data needed to reproduce its confirmed result; that removal of the source or a newer release does not alter that result; and that an incompatible algorithm preserves it and explains the limitation without silent recomputation. The implementation plan asks for explicit source updates with a route back.

## Alternatives

1. Recompute a frozen work with the current algorithms and show a warning: REQ-085 forbids silent recomputation, and the confirmed colours would change under the operator.
2. Pin by release only and re-resolve laser, lens and titanium by name: a renamed or re-measured setup would move the work.
3. Store the whole snapshot with the work: a release is kept once under labs/ and protected from removal while works use it.

## Decision

A photograph vector work or a photo work may take its colours and curves from one connected release, chosen when the work is made with the laser, lens and (for a vector work) titanium the release measured; traced vector works and the knowledge stages use the workshop's own measurements only in v1. The work's pin (data_json.evidence_source) stores the release id, laboratory, content hash, release date, the release's and the current algorithm versions, the chosen laser, lens and titanium by release UUID and snapshot id, the records withdrawn when it was pinned (they stay hidden for this work), and the confirmed result: a vector work keeps the palette it was made with (every entry with its complete recipe) in a file of the workshop, a photo work keeps the LightBurn file it last exported. The work is engraved on the workshop's own laser: the cleaning layer, the limit checks before a file is written and the engraving checks of its own photographs are the own laser's; the colour map its dots are picked on and all curves and palettes are the release's. A work is frozen when its release is no longer on this computer or an algorithm version differs from the pin's: its screen shows the confirmed colours, zones or file with the reason, and nothing is calculated again. Only an explicit update moves a work: the preview shows the target release and the colours the work uses before and after with their ΔE (vector), or the scale at Min…Max before and after (photo), and nothing changes until it is confirmed; the earlier pin is kept in source_versions so that the work can go back, and a release that an earlier pin names is not removed. A newer release of the laboratory is shown as a condition and never applied by itself. Copies of a work keep its pin.

## Reason

The pin and the kept palette or file are exactly the data needed to show and export the confirmed result after the release or the algorithms are gone, and the explicit, previewed update with a route back keeps every change of a work's result the operator's decision.

## Consequences

evidence_source.py holds the pin, the freeze rules, the choices, the update preview and the own-limit check; vector_job.py and photo_work.py read through it. REQ-085 criteria 1, 2, 4-7 are covered by tests/test_lab_sources.py.
