## Context

DEC-028 places the cloud API on Vercel with Neon PostgreSQL, and DEC-040 requires a managed authentication provider without naming it. The owner's Neon organisation and Vercel team have no project for the workshop.

## Alternatives

1. Clerk as a separate sign-in provider with Neon and Vercel
2. No cloud deployment yet; cloud code tested locally only

## Decision

Create a new Neon project and a new Vercel project in the owner's accounts and use Neon Auth (managed, stored with the same database) for sign-in and account recovery. Start on the free plans.

## Reason

The owner approved creating the resources and chose Neon Auth on 2026-10-24.

## Consequences

Desktop sign-in opens the system browser on a page served by the Vercel project and returns to the application through a validated loopback callback. The API verifies Neon Auth tokens; ownership and invitations are enforced on the server. Destructive operations on these resources are never run without asking the owner.
