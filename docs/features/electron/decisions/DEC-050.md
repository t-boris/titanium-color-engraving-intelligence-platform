## Context

A recipe keeps every setting tag of the measured LightBurn layer (REQ-012), and some tags carry text the operator typed: layer names, sub-layer names, file names. REQ-083 forbids private text in a release, but a recipe must stay complete so that a recipient can engrave it and recipes that differ only in such a tag stay distinct.

## Alternatives

1. Drop free-text tags from the published recipe: recipes that differ only there would merge, and the recipient's file would not reproduce the measured one.
2. Publish the text: it is private (names, notes).
3. A random per-release replacement: equal texts would not match across releases of one laboratory.

## Decision

Numbers and the words of enumerated settings are published as they are. Any other text of a setting is replaced by a token: "tok:" + the first 16 hex characters of HMAC-SHA256 of the text under a laboratory secret that is generated once, kept in the workshop and never exported. Equal texts give equal tokens, the text cannot be read back, and the token takes the text's place in the recipe key. Setting keys that are not plain identifiers are tokenised the same way. The label of a layer in a release is C plus the layer's lowest index (C00, C01 …); the operator's layer names never leave the workshop.

## Reason

A keyed hash keeps the recipe complete and distinct without disclosing the text, and stays stable across releases of the same laboratory, so a recipient can recognise the same recipe in a newer release.

## Consequences

The privacy test checks that none of the workshop's private markers appear in a release in raw, base64, hex or percent form. The laboratory secret is part of the workshop backup.
