## Context

Нужно проверить обмен между двумя компьютерами до создания облака и избежать переноса внутренних путей и SQLite-схемы.

## Alternatives

1. Копирование рабочей SQLite.
2. ZIP с изображениями и базой.
3. Передача только RGB-квадратиков или сериализованного ML-объекта.

## Decision

Предлагается независимый UTF-8 JSON-формат .tcelab с JSON Schema, числовыми данными, UUID, версиями и проверкой целостности.

## Reason

Не зависит от ОС, не содержит исполняемых объектов и может использоваться одинаково при файловом и онлайн-обмене.

## Consequences

## Контракт переносимой лаборатории — предложение v1

Предлагается .tcelab как UTF-8 JSON-документ с канонической сериализацией. В v1 без ZIP, вложений, изображений, произвольных URL ресурсов и сериализованных исполняемых моделей. Один экспорт может содержать несколько установок, но каждая запись явно привязана к одному снимку установки и материала.

| Раздел | Содержание |
|---|---|
| manifest | schema_version, origin_lab_id, release_id, release_number, created_at в UTC, producer_version, algorithm_versions, content_sha256, counts, capabilities, license, attribution |
| lab | Публичное название, описание, автор/организация, выбранная владельцем публичная информация |
| equipment | UUID физического источника, модель и доступные характеристики лазера, снимок линзы/поля/пятна, неизвестные значения явно null |
| materials | Семейство, марка, толщина, поверхность и существенные условия; публичное имя партии только при выборе владельцем |
| measurements | UUID наблюдения и независимой гравировки, Lab, полные применимые параметры, режим, условия, измерительная основа, критерии пригодности и качества |
| tone_profiles | Режим слоя и параметры, ось tone/power, числовые bins, количество пикселей/повторов и признаки пригодности; без пространственных масок |
| provenance | Ссылки между числовыми объектами, версия алгоритма, заявленная калибровка, замены и отзывы; без файловых путей |
| recipe_summaries | Необязательные сводки, проверяемые/пересчитываемые из опубликованного набора; не источник новых независимых наблюдений |

Хеш вычисляется по каноническому содержимому с исключением самого поля content_sha256. Хеш обнаруживает изменение содержимого, но не доказывает авторство; авторство онлайн-выпуска устанавливает сервер. Импорт из файла помечается как «метаданные автора не подтверждены сервером», пока связь с серверным выпуском не проверена.

Разрешённые поля задаются явной схемой. Не экспортируются RAW, исходные/встроенные изображения, превью исходников, LightBurn-геометрия, координатные маски, исходные имена и пути файлов, приватные заметки, сообщения AI, токены, email и серийный номер по умолчанию. Публичные названия вводятся отдельно; свободный текст предварительно показывается владельцу.

Фильтрация состава меняет статистику: сводки строятся только по включённым наблюдениям. Нельзя экспортировать один удобный цвет, но сохранить счётчик пяти повторов, оставшихся за пределами публикации. Несовместимые способы измерения не усредняются. Данные без референса не получают статус калиброванных при импорте.

Предлагаемые начальные технические пределы: 16 MiB на .tcelab, до 50 000 наблюдений, до 5 000 профилей и до 256 bins на профиль; проверяются фактический размер UTF-8, вложенность, конечность чисел, уникальность id и целостность ссылок. Это защитные проектные лимиты, а не измеренная производительность. Их пересмотреть после пробы с реальными данными. Более новые major-версии схемы отклоняются без изменения базы; совместимые minor-версии обрабатываются по объявленной политике.

### Версионирование

Одна лаборатория имеет стабильный UUID. release_id уникален, номер выпуска монотонен внутри лаборатории и назначается сервером при онлайн-публикации. Файловый экспорт имеет собственный release_id, может быть неопубликованным и не придумывает серверный номер. После публикации пары release_id + content_sha256 неизменяемы. Совпавший release_id с другим содержимым — ошибка целостности, не обновление на месте.

Локальная работа хранит origin_lab_id, release_id, content_sha256, выбранные recipe_id и версию вычислительного алгоритма; нужный снимок сохраняется локально вместе с данными для воспроизведения результата.



Ссылки на записи должны образовывать замкнутый набор; превышение лимита не ведёт к молчаливому обрезанию. В v1 UUID локальных наблюдений назначаются отдельно от integer primary key и сохраняются при повторном экспорте. Точный JSON Schema и golden fixtures — результат DEV-01.
