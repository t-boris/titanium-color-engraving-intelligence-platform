## Context

Автообновление не должно удалить мастерскую или запустить старый код поверх несовместимой новой базы.

## Alternatives

1. Хранить пользовательские данные внутри app bundle.
2. Копировать только titanium.sqlite без WAL и пользовательских файлов.
3. При ошибке нового приложения автоматически запускать старое на новой схеме.

## Decision

Данные хранятся вне установки. Перед миграцией создаётся согласованная резервная копия SQLite и необходимых неизменяемых файлов. Обновление устанавливается на безопасной границе операций; rollback допускается только с совместимой схемой или восстановлением согласованного набора данных.

## Reason

Сохраняет рабочие исходники и воспроизводимость при сбоях обновлений.

## Consequences

Копия SQLite создаётся через backup API или эквивалент с учётом WAL. Для изменяемых файлов нужен quiesce/checkpoint или полный manifest снимка. Нет места/прав — миграция не начинается. Первый запуск новой версии сохраняет диагностируемую ошибку. Ключи/токены не включаются в общие публикации. Бэкап хранится локально или в выбранной пользователем папке; это отдельный формат от .tcelab.
