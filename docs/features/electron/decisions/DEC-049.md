## Context

DEC-024 describes a release as one JSON document; Q-008 (answer B) asks for streaming export and import in constant memory. A single nested JSON document cannot be validated and hashed incrementally without holding it whole. DEC-024 also lists the sections but has no record per photograph, while palettes, tonal curves and the engraving identity (DEC-045) need one.

## Alternatives

1. One nested JSON document (DEC-024 as written): simple, but not incremental; a 50 000-measurement release would be parsed whole.
2. SQLite file as the exchange format: binary, hard to sign and diff, and the schema would be the file format.
3. JSON Lines without canonical form: hashes would depend on the producer's serializer.

## Decision

A .tcelab v1 file is UTF-8 text, one record per line, every line in RFC 8785 canonical JSON form. Line 1 is the manifest (format, schema_version, origin_lab_id, release_id, release_number, created_at, producer, algorithm_versions, capabilities, usage_terms, attribution), line 2 the laboratory, then the sections in the fixed order equipment, materials, captures, measurements, tone_profiles, provenance, each record prefixed by its section name and carrying its seq, and the last line the end record with the counts and the content SHA-256 of every line before it. A captures section (one record per accepted photograph: engraving id, equipment, material, basis, experiment, over_fills) is added to DEC-024's sections. The reader checks each line as it comes against the schema (schemas/lab-v1.schema.json, additive allowlist), the resource policy (bytes, line bytes, records per section, bins, depth, string length) and the canonical form, and confirms the counts and the hash at the end; the writer writes to a temporary file and renames it whole. Reading and building the snapshot use constant memory; writing keeps only its indices (identity, role, label per measurement).

## Reason

Canonical lines make the content hash independent of the producer, let the reader validate and hash in one pass without holding the release, and keep the format diffable and signable. The captures section gives every measurement and tonal profile its photograph and engraving, which the engraving identity of DEC-045 needs.

## Consequences

lab_format.py (stdlib only, shared with the cloud) implements the encoder, the strict decoder (duplicate keys, NaN and Infinity, depth refused), the reader, the writer and the policy. A change of the line layout is a major schema version; new sections or fields are additive.
