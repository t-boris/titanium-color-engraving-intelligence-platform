## Context

The user explicitly requested careful, detailed use of .dde/prototypes/initial/export/initial-v10.zip during specification development.

## Alternatives

1. Use the feature documents without incorporating the prototype.
2. Treat all prototype behavior and demonstration values as approved production requirements.

## Decision

Use initial-v10.zip, including SPEC.md, CHANGES.md and the prototype source files, as a reference for the Product + System Specification alongside accepted requirements and decisions.

## Reason

The prototype provides concrete interface behavior and review history that must inform the implementation-ready specification.

## Consequences

The prototype's screens, flows and validation rules are the reference for the browser UI; its demonstration formulas (Lab means, nearest sample, fixed repeat counts, JSON '.lbrn2' export) and its listed code defects are not production behaviour. Where the prototype and the requirements differ, the requirements and accepted decisions win (for example the ΔE threshold applies to expected color error, REQ-004). Independence of repetitions is defined by DEC-021, not by the prototype's pieceId rule.
