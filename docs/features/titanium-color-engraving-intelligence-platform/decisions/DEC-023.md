## Context

The task requires bumping the version "according to the project's versioning rules", but the repository has no version file, no tags and no rules.

## Alternatives

1. Calendar versioning.
2. No versioning until a later release.

## Decision

Use Semantic Versioning. The single source of the version is `pyproject.toml`. The first implementation release is `0.1.0`. A merged release is tagged `v<version>`. The running application reports its version at `GET /api/version`.

## Reason

SemVer is the common default for Python packages and gives the deploy step something concrete to verify.

## Consequences

Proposed only. Needs the user's confirmation or a different rule.
