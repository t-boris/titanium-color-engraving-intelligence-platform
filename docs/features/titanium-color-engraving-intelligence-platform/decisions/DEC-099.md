## Context



## Alternatives

1. Write the version into index.html or the scripts at build time: a second copy of the version, and cached pages would show a version the server no longer has.
2. Show it in the footer or in Settings: the operator asked for the header.

## Decision

The router asks GET /api/version once when the first header is built, keeps the answer and fills every `.app-version` label (v<version>, hint \"Версия приложения\") between the menu button and the user chip; an empty label is hidden and a failed request is tried again at the next screen.

## Reason

DEC-023 made GET /api/version the only place that reports the version, so the operator could not tell which release was running after a deploy. The server's answer is the version of the running process, the thing the operator wants to know; it does not show that the browser loaded fresh scripts (reload with Cmd+R as before). Nothing is baked into the scripts, so there is no second source of the version to keep in step with pyproject.toml.

## Consequences

The header gains one small label and one request per page load; DEC-023 is unchanged (the version is still reported at GET /api/version).
