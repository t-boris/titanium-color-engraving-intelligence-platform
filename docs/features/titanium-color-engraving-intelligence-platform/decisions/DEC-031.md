## Context

After the first six plan items were implemented, the implementing agent asked how to proceed with the remaining items (I-7 to I-10), the HTTP API, the browser UI and the pull request, CI, merge and deploy steps. Several behaviours the requirements leave open were implemented as proposed decisions (DEC-023, DEC-024, DEC-026 to DEC-030).

## Alternatives

1. Stop adding features, merge I-1 to I-6 with a minimal UI and leave I-7 to I-10 for later pull requests.
2. Pause until the user has reviewed the proposed decisions.

## Decision

Implement everything in the plan: discrete and continuous conversions, post-engraving analysis, the offline Experiment Designer, the HTTP API and a browser UI, then the pull request, CI, merge and deploy steps. Proposed decisions stay `proposed` and act as working defaults. The pull request lists every one of them so the user can accept or change them.

## Reason

The user chose this option.

## Consequences

Anything built on a proposed decision may need rework if the user changes that decision. The formulas and thresholds each live in one module so a change stays local.
