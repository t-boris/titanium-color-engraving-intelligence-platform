## Context

The operator opened an exported work in LightBurn: the picture was upside down (the mouth above the glasses), and two straight slivers crossed the woman's face. The plates already carry MirrorY=True because LightBurn's galvo canvas shows a top-down layout upside down. The slivers were four Bezier edges of layers 15 and 27 around (56, 72.5) mm that had a handle at one end only: the corner end was written as 'no handle' (c1x1). LightBurn reads a missing handle as the origin of the shape, so each edge swung out towards the top-left corner and back; the far end of the curve computed with the origin as the missing handle lies at (33.1, 42.8) mm, where the sliver ends in the screenshot.

## Alternatives

1. Flip the coordinates at export (every later step that reads the file would meet a mirrored picture)
2. Leave the flip to the operator (they flipped each work by hand, and the check had to find the reflection)
3. Use straight edges where a handle is missing (changes the shape of the borders)

## Decision

The vector job export records export_mirror_y=True on the plan and writes MirrorY="True", exactly as the plates do; the coordinates do not change. Wherever a Bezier edge leaves from or arrives at a vertex, that vertex's handle is written, on the vertex itself when it is a corner; a vertex that no curved edge uses keeps 'no handle'.

## Reason

The plates' flag is the proven way to have this canvas show a top-down layout upright, and it leaves the geometry, the alignment and the check untouched. Writing both handles removes the case LightBurn has to guess without changing any curve.

## Consequences

Files exported before this change keep MirrorY=False; the plan flag changes at the next export, so a file saved from an older export is read against the newer flag and may be reflected once; the alignment search handles the reflection. The effect of the flag in the operator's LightBurn is confirmed only by opening a new export.
