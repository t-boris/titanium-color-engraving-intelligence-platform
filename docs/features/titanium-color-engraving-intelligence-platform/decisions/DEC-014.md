## Context

Stability analysis needs explanatory context (material batch, focus) to separate color instability from changed conditions. The user prefers not to require extra fields: a LightBurn file carries the layer parameters and a calibration plate carries its parameter grid.

## Alternatives

1. Mandatory laser profile, material/sheet ID and focus for rig plates; relaxed for legacy import
2. All fields mandatory everywhere with explicit 'unknown'

## Decision

For every observation the laser parameters (power, frequency, speed) are taken from the artefact: from the LightBurn file layers on import, from the paired LightBurn file for rig plates as well; the plate definition linked by the experiment identifier is kept for experiment identity and geometry linkage and is compared with the file (DEC-017). Laser profile is the only mandatory context. Material profile/sheet ID, focus, date and notes are optional and default to 'unknown'. Fact: .lbrn/.lbrn2 files do not record focus, material batch or profile constants.

## Reason

Minimizes input friction for both plate workflows and archive import, as the user requested.

## Consequences

Stability analysis can attribute deviations to batch or focus only where those fields were filled in; the UI should offer them as quick optional fields with 'same as last plate' defaults. The specification must state this limitation explicitly.

Amended by DEC-017: for calibration plates the paired LightBurn file, not the plate definition, is the authoritative source of power, frequency and speed. A difference from the plate definition blocks acceptance until the operator corrects the pair or confirms the attached file.
