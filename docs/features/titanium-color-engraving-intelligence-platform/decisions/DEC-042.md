## Context

The operator selected option B. Existing code still uses profile identifiers, although ingest.layer_report already reads pulse width, line interval and passes without rejecting them merely for differing from profile constants.

## Alternatives

1. Retain versioned laser profiles containing engraving constants.
2. Store engraving settings on plates and plans, with equipment facts on laser devices.
3. Retain an optional named preset as a separate operator-facing entity.

## Decision

Store pulse width, line interval and passes directly on each plate and EngravingPlan, including per-layer values where applicable. Store equipment facts on the selected laser device. Partition comparable knowledge by device, historical lens configuration and equal pulse width, line interval and passes; within each partition, model power, frequency and speed. Supersede the profile-constant and profile-version restrictions in DEC-005, DEC-022, DEC-029 and DEC-035; retain their other protections and estimation rules.

## Reason

Engraving settings belong to the job, while comparable observations must still describe the same equipment and conditions.

## Consequences

Remove the profile creation prerequisite and profile screen. Replace profile-version-based comparability in modeling, prediction and maturation with device, historical lens configuration and recorded engraving settings. Preserve existing observations and their provenance.
