## Context

The operator chooses titanium colours for a work and asked where a colour comes from (tests or an existing work) and for a way to swap it for a more stable one. The data has no field for it: all the operator's engravings are uploaded files, tests and finished works alike, with no plan of the system for most of them, and the colour map says only how many engravings agree.

## Alternatives

1. Ask the operator to tag each upload as a test or a work (more work for the operator, and the 16 existing uploads would stay untagged)
2. Rank by the confidence number alone (one engraving has no number, so the most common case could not be told from a bad one)
3. Replace automatically by the nearest stable colour (the operator wants to choose, and a swap changes how the work looks)

## Decision

An engraving is a test when it is a calibration plate, a laser capability test or a parameter matrix (a matrix cell in its evidence), and a work otherwise; a vector work also names itself. Each palette entry carries the engravings it is known from with that kind. A colour is stable when two or more independent engravings agree, single when it was engraved once, and doubtful when the engravings disagree (the circle of the colour map is smaller than that of one engraving, or the colour changed under the same settings). The picker orders by closeness, stability or speed, can show only the confirmed colours, and offers the confirmed colours nearest to an unconfirmed one.

## Reason

It uses what the system already knows (the plan mode, the matrix cell, the agreement of engravings, DEC-084 and DEC-091) and invents no new score, so the words in the editor, the picker and the colour map are one thing.

## Consequences

An upload of a test layout made by hand with no matrix counts as a work. The kind is derived, never edited. Palette entries are larger (the sources of each recipe travel with it).
