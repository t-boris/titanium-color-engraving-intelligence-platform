## Context

DEC-004 and REQ-011 deliberately left the implementation technology open. Implementation cannot start without a choice. The hardest parts of the product are RAW decoding, reference-chart detection and color correction, registration-marker detection and an uncertainty model.

## Alternatives

1. Node.js/TypeScript with Fastify and SQLite, reusing the prototype's UI code.
2. Go with a single binary, embedded SQLite and UI.
3. Another stack.

## Decision

The application is a single local Python 3 process: FastAPI serves the JSON API and the browser UI as static files, SQLite stores the data locally, and OpenCV (with the contrib modules), rawpy, numpy, scipy and scikit-learn do RAW decoding, chart-based correction, marker detection and the color-space model. pytest runs the automated tests.

## Reason

The user chose this option. Python has mature libraries for every computer-vision, RAW and statistics task the specification needs, and the process still satisfies REQ-011: one local process, local storage, no internet, reachable from a tablet on the local network.

## Consequences

REQ-011 stays technology-neutral as a requirement; this decision is the implementation choice that satisfies it and does not change DEC-004. The prototype's JavaScript is a UI reference (DEC-019), not server code. The server binds to the local network only on explicit user configuration. The packaged application is a Python package with a console entry point.
