## Context

REQ-004 matches an image color to a validated or production titanium color "only if the expected color error is within a user-configurable delta E threshold". The prototype compared only the distance between the requested color and the chosen sample. These are different quantities.

## Alternatives

1. Compare only the distance between the requested color and the predicted color (prototype behaviour).
2. Compare only the knowledge entry's own expected color error and ignore how far the sample is from the request.

## Decision

For each candidate the system computes two numbers and shows both: the distance delta E between the requested Lab and the predicted Lab, and the knowledge entry's expected color error (DEC-029). The expected color error of the match is their sum. The match is accepted only if that sum is not above the threshold; otherwise the color is unreachable. The nearest candidate by distance is the one tested.

## Reason

The sum is a conservative bound: the printed color can miss the request by the gap between sample and request and also by the sample's own measured scatter. It makes the requirement's wording ("expected color error") and the prototype's distance both visible instead of silently choosing one.

## Consequences

Proposed only. The sum is an engineering choice, not a statistical bound. With no saved delta E tolerance the threshold is an explicit per-plan input, never defaulted silently; the conversion screen shows its current value.
