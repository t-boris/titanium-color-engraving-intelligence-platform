## Context

The user has an archive of finished titanium artworks with their LightBurn project files and photographs. He wants to feed these into the system so it learns colors and stability from real work, not only from calibration plates. These photos were not taken on the controlled rig, carry no registration markers or reference chart, and the LightBurn file does not record material batch, focus or laser profile constants.

## Alternatives

1. Treat imported pairs as regular observations with reduced weight / inflated error
2. Use imports only as targets for the Experiment Designer, not as observations
3. Do not support historical import; only rig-photographed plates and marker-equipped plans

## Decision

The system shall support importing a LightBurn file (.lbrn/.lbrn2) together with a photograph of the finished engraving. Layer parameters (power, frequency, speed) and fill geometry are parsed from the file to reconstruct an EngravingPlan; the photo is aligned manually by image corners (as in DEC-010). Each layer region yields observations stored with provenance = 'legacy/uncontrolled'. Such observations enter the experiment database and inform the color-space model and Experiment Designer, but by default do not count toward repetition thresholds for promotion to 'validated'. (Weighting rule proposed by the facilitator, pending user confirmation.)

## Reason

Reuses the existing post-engraving analysis path and lets the model bootstrap from real artwork quickly, while preserving the accepted principle that physical measurements under controlled conditions remain the source of truth and that production knowledge matures only through repeated controlled observations.

## Consequences

Superseded by DEC-015 (Q-014) and DEC-016 (F-001). The user clarified that these works are not legacy: every observation is a LightBurn file plus a photograph taken on the fixed rig with the reference chart. The 'legacy/uncontrolled' provenance tier, its exclusion from validation repetitions and the weighting rule that was pending user confirmation are all removed. This record is kept for history only and must not be implemented.
