## Context

The source calls the module an 'AI Experiment Designer' without defining what AI means; the choice affects external dependencies, reproducibility and how the module is specified.

## Alternatives

1. Fully algorithmic without any LLM
2. LLM-driven plate proposals from a color-space summary

## Decision

Plate proposals are produced by an offline algorithmic core: the color-space model with uncertainty (e.g. Gaussian-process or interpolation with error estimates) plus an acquisition function scoring candidate parameter sets by uncertainty, gaps, instability and target colors. An external LLM may optionally generate a human-readable explanation and hypotheses for the operator; it never selects parameters or modifies data, and the system is fully functional without an API key.

## Reason

Keeps the core deterministic and testable and respects the principle that measurements are the source of truth, while giving the operator the explanations he expects from 'AI'.

## Consequences

Specification must describe the acquisition function and model inputs explicitly; LLM integration is an optional adapter with a no-op fallback. The user's open concern about scanning images and mapping colors to LightBurn settings is handled by the universal ingestion pipeline (REQ-015), not by the Designer.
