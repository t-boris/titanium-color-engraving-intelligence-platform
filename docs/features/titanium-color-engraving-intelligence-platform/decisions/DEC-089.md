## Context

Operator, 2026-10-20: "Who said Q-Pulse 300 is not supported by the laser? Of course it is. I entered it and it works fine." REQ-017 criterion 2 and DEC-035 refused any pulse width that was not one of the 17 steps of the manufacturer's cut-off table (photographed from the laser documentation), on the reading that the laser ignores any other. The operator's experiments use 300 ns (113 observations), 3, 5, 7, 8 and 10 ns; the rule marked all of them "excluded from parameter recommendations", so 10 of 17 accepted checks and the whole 100-cell matrix of check 54 never reached the model. Asked which rule to use, the operator chose: any value from 1 to 500 ns.

## Alternatives

1. Add the values the operator uses as extra rows of the passport table, each with a cut-off frequency typed by hand
2. Accept any width but leave the cut-off unknown outside the table (no power loss modelled)
3. Keep the rule (refused by the operator: the laser takes these widths)

## Decision

A pulse width is valid when it lies between the smallest and the largest width of the laser's table (1-500 ns for the JPT M7). The table stays what it is, the manufacturer's cut-off frequencies; for a width between two steps the cut-off frequency is interpolated (straight line in log width and log frequency between the neighbouring steps; next to a CW step, the cut-off of the other neighbour), and the figures that use it say it is interpolated. A width outside the range is refused with the range. The default pulse width of a laser (DEC-086) follows the same rule. The design pickers keep offering the table's widths; a value typed elsewhere (experiment file, matrix, supplied setting, prediction) is accepted when in range.

## Reason

The operator knows their laser: it takes these widths. The cut-off table was the only source of the restriction, and interpolating it keeps the power-loss model working for widths the table does not list, instead of dropping 138 observations from the model.

## Consequences

Observations already accepted with an off-table width keep model_eligible 0 (immutable) until the experiment is measured again. The interpolated cut-off is an estimate, not a manufacturer's figure: the power factor at a frequency below the cut-off of such a width is approximate, and the screens say so. Whether the real laser rounds the width to its nearest internal step is not known; if the operator learns that it does, the interpolation is replaced by that step. Supersedes REQ-017 criterion 2 and DEC-035 (refusal of an unsupported width) and the "one of its steps" part of DEC-086.
