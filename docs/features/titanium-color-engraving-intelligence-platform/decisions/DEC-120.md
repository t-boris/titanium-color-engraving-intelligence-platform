## Context

The operator scales or moves the whole file of a work in LightBurn to the plate at hand, markers and cleaning rectangle included (pair 116: the 172 x 180.5 mm export scaled to a 153 x 153 mm plate, 89% x 85%). Up to 0.25.2 the check mapped the markers found in the photograph to the plan's positions. A homography fitted to four markers absorbs any scale, so the photo space was stretched by the inverse of the scale and the file's shapes, drawn in their own millimetres, landed beside the engraving: vectors found by coincidence, colours sampled off the shapes, no warning (BUG-006). A plate already located the plan's markers through the file's cleaning rectangle, but only as a move of the same size; a work did not even that, so a work merely moved on the bed was measured beside its engraving too.

## Alternatives

1. Align to the plan and stretch the file's shapes to the export's size: the colours would be sampled on the shapes, but every size (line widths, areas, the placement reported) would be the export's, not the plate's.
2. Compare the file with the export (left_behind.compare) and refuse a scaled file: refuses a legitimate job; the hidden layers left behind are a different question (REQ-050).
3. Read the absolute scale from the ruler or the marker size: an independent check worth adding later, not a replacement for the file's own geometry.

## Decision

The engraved file's cleaning rectangle is the plan's extent as the file has it (the invariant lightburn.normalize_saved_orientation already relies on). Its size against the extent gives the scale on each axis, its corner the offset. Before the alignment the plan's marker geometry (extent, ArUco squares with a height of their own, QR, labels) is scaled about the extent's corner to that size (ingest._plan_as_engraved), and _align takes the file offset from the cleaning rectangle for every marked plan, as it did for a plate. The markers found in the photograph are thus mapped to where the file has them, and the file's shapes are measured as they are, in the plate's millimetres. The report carries alignment.file_placement (scale and offset); when the scale is not 1 the operator is warned that the file is W% by H% of the export and the engraving is measured at that size. A plate still demands the plate's size. The hidden layers that stayed behind when the rest was scaled remain left out (REQ-050).

## Reason

The photograph shows the plate as it was engraved, and the engraved file is the only description of that; the plan knows the markers' pattern and identifier but not the size the operator gave the job. Using the file's own cleaning rectangle keeps the existing invariant, needs no second comparison with the export, and gives physical millimetres.

## Consequences

0.25.3. Pair 116 finds 158 of 158 closed vectors (mean edge support 0.70 against 0.43). A file at the export's size is measured as before; a file only moved on the bed is now measured on its engraving too. The ruler's pixel pitch is a possible later check of the absolute scale.
