## Context

REQ-021 asks for an image to become an editable vector representation and a standard LightBurn project, with task strategies, a preview of weak evidence and review before export, but sets no method. Until 2026-10-18 an image was reduced to 160 px and pixel runs became rectangles, with only discrete, tonal and colour-path strategies. The operator chose a contour vectoriser in the application.

## Alternatives

1. Strategies only over the existing rectangles (no editable vectors)
2. Defer REQ-021 to a later change

## Decision

The image is reduced per strategy (discrete colours to the chosen palette, a threshold for text and line art) and traced with OpenCV (already a dependency, no new library): fill and colour regions as closed paths with their holes, text and line art as stroke paths, each simplified with an editable tolerance in millimetres and tiny regions merged into their neighbour. Each region keeps its source colour and pixel area, its task and its settings. The operator reviews an SVG preview where a region's task and settings can be changed, regions deleted or merged and the tolerance changed; regions without adequate evidence are marked. Export writes LightBurn Path shapes with holes; editing of individual nodes stays in LightBurn.

## Reason

The operator chose it. Contours give real, editable geometry in LightBurn without a new dependency; node editing would duplicate LightBurn.

## Consequences

The LightBurn writer gains Path shapes with sub-paths. The existing discrete, tonal and colour-path conversions keep working; the vector job links its source image, vector document, settings, predictions, exported file and later result as one work record.
