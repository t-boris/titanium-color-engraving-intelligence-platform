## Question

Which implementation stack should the single local web process use? DEC-004 and REQ-011 deliberately leave the implementation technology open.

## Why it matters

The first implementation cannot start without a stack. The choice decides how RAW decoding, reference-chart detection, marker detection and the color-space model are built, and how the application is installed and run locally.

## Options

- **A**: Python 3: FastAPI + SQLite, with OpenCV, rawpy and numpy/scikit-learn. The UI is served as static files from the same process.
- **B**: Node.js/TypeScript: Fastify + SQLite, reusing the prototype's UI code.
- **C**: Go: a single binary with embedded SQLite and UI.
- **D**: Something else.

## Recommended

A — The hardest parts of the product are RAW decoding, chart-based color correction, marker detection and an uncertainty model, and Python has mature libraries for all of them.

## Answer

A. Python 3: FastAPI + SQLite, with OpenCV, rawpy and numpy/scikit-learn (RAW, chart correction, marker detection and the uncertainty model). The UI is served as static files from the same process.
