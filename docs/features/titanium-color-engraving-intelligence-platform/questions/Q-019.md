## Question

Which language should the browser UI use? The approved prototype v10 is in Russian and its SPEC.md says user-facing names and messages stay Russian, while the server's error messages are in English.

## Why it matters

The operator reads the messages that block or explain a decision, such as a chart that was not detected or a file that differs from the plate definition.

## Options

- **A**: Russian UI; server messages shown by the UI are translated; API and docs stay English.
- **B**: English UI.
- **C**: Russian screens now, English server messages left as a known gap.
- **D**: Both languages, switchable.

## Recommended

A — The approved prototype is in Russian and the operator reads Russian.

## Answer

A. Russian UI, matching the prototype. I translate the server messages the UI shows, and keep English in the API and the docs.
