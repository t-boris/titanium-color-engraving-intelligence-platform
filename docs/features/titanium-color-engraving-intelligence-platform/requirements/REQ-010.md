## Statement

The first version shall support one material profile family (titanium) and one laser profile with three variable axes — power, frequency, speed — while pulse width, hatch/line interval and passes are stored as constants of the laser profile. For every observation, including calibration-plate and rig-plate observations, power, frequency and speed shall be sourced from the corresponding layers of the paired LightBurn .lbrn/.lbrn2 file. For calibration-plate and rig-plate observations, the plate definition linked by the experiment identifier shall be retained for experiment identity and geometry linkage. The system shall compare power, frequency and speed from the paired LightBurn file against the linked plate definition. If those parameters differ, observation acceptance shall be blocked until the operator corrects the pair so that the parameters agree or explicitly confirms that the attached LightBurn file was used for the physical engraving. Following such confirmation, the paired LightBurn file shall remain authoritative for power, frequency and speed. Every detected discrepancy and any operator confirmation shall be recorded with the observation. Laser profile shall be the only mandatory context. Material profile, material batch/sheet ID, focus, date and notes shall be optional observation metadata, defaulting to 'unknown', with quick optional UI fields offering 'same as last plate' defaults. Since .lbrn/.lbrn2 files do not record focus, material batch or profile constants, profile constants shall be sourced from the linked laser profile version. Every measurement shall preserve the full parameter vector, including profile constants. Changing a profile constant shall create a new profile version, and data from different versions shall not be merged silently. The profile model shall allow adding further axes later without migrating existing experiment data. Stability analysis shall attribute deviations to material batch or focus only where those metadata fields were supplied, and this limitation shall be stated explicitly in the specification and UI. Per DEC-022, pulse width and line interval recorded in a LightBurn layer are compared with the constants of the linked laser profile version; a layer whose values differ is imported with a warning, marked not comparable, and kept out of the color-space model and the repetition counts.

## Acceptance Criteria

- [ ] The first version supports one titanium material profile family and one laser profile with power, frequency and speed as variable axes.
- [ ] Calibration plates are generated as grids over power × frequency, with speed represented as a plate series or third dimension.
- [ ] Pulse width, hatch/line interval and passes are stored as laser profile constants and recorded with each experiment.
- [ ] Every observation, including calibration-plate and rig-plate observations, sources power, frequency and speed from the corresponding layers of the paired LightBurn .lbrn/.lbrn2 file.
- [ ] For calibration-plate and rig-plate observations, the plate definition linked by the experiment identifier is retained for experiment identity and geometry linkage.
- [ ] For calibration-plate and rig-plate observations, the system compares power, frequency and speed from the paired LightBurn file against the linked plate definition.
- [ ] If any compared parameter differs, observation acceptance is blocked until the operator corrects the pair so that the parameters agree or explicitly confirms that the attached LightBurn file was used for the physical engraving.
- [ ] An operator confirmation permits acceptance with the discrepancy retained and power, frequency and speed sourced from the paired LightBurn file.
- [ ] Every detected parameter discrepancy is recorded with the observation.
- [ ] Any operator confirmation that the attached LightBurn file was used for the physical engraving is recorded with the observation.
- [ ] Laser profile is the only mandatory context; material profile, material batch/sheet ID, focus, date and notes are optional and default to 'unknown' when not supplied.
- [ ] The observation UI offers material profile, material batch/sheet ID, focus, date and notes as quick optional fields with 'same as last plate' defaults; fields without a previous value default to 'unknown'.
- [ ] Import does not treat focus, material batch or profile constants as recorded in .lbrn/.lbrn2 files; profile constants are sourced from the linked laser profile version.
- [ ] Every measurement stores the full parameter vector, including the laser profile constants, and links to the laser profile version used.
- [ ] Adding further variable axes does not require migration of existing experiment data or cause loss of previously stored parameter values.
- [ ] Changing a laser profile constant creates a new profile version; data from different versions are not merged silently.
- [ ] Stability analysis attributes deviations to material batch or focus only for observations where the corresponding metadata was supplied.
- [ ] The specification and stability-analysis UI explicitly state that unknown material batch or focus limits attribution of deviations to those factors.
- [ ] Pulse width and line interval read from a layer are compared with the linked laser profile constants; a layer that differs is imported with a warning, marked not comparable, and excluded from model updates and repetition counts (DEC-022).
