## Context

Operator, 2026-10-19, after 0.8.0 was live: "Векторная работа должна где-то как-то сохраняться. То есть, что мы выбрали, как она выглядит. ... И возможность переделать. И, пожалуйста, переделай UI намного-намного более удобным, чтобы не надо было вообще скроллить." A work was already stored (plan row, document file, source image), but the screen "Векторная работа" held only the creation form: a work could be reached only by its address (#/vector?plan=22), and its page was several screens tall. Work 22 was deleted from the interface by mistake the same day and had to be restored from a backup.

## Alternatives

1. A list without copies: 'redo' is opening the work and changing it in place (rejected by the operator)
2. A step-by-step wizard, one step per screen (rejected: back-and-forth between steps)
3. Tabs over the full width of the page (rejected: the picture would have no room beside the tools)
4. Soft deletion with an archive (not asked for; the store keeps hard deletion for never-photographed plans)

## Decision

1) The screen "Векторная работа" opens with the saved works: a thumbnail of the coloured result (drawn from the stored layers, cached with the render cache), name, date, size, algorithm, colours, layers and the way it was coloured (an AI style included). Each has Open, "Сделать копию" and Delete. A copy is a full independent duplicate (own image and document files; colouring, variants and settings kept; undo, redo and exports reset), opened at once, the original untouched; deletion asks first and says the work cannot be brought back. The creation form moves to "Новая работа" (#/vector?new=1). 2) A photo work is one screen: a header (back to the list, name and summary, plan, copy, the file), left tabs Разбиение, Цвета, AI, Варианты, Файл, the editor's picture in the middle, its panel on the right in tabs Кисть, Слои, Цвета. The page itself does not scroll (the side menu folds away like on a phone, Menu opens it); only a list too long for its panel scrolls inside it (the 28 source colours). The open tab is remembered by the browser. The wide per-colour table opens in a window. On a narrow screen the columns stack and the page scrolls as before. Works made by other strategies (fill, text, line) keep their longer page.

## Reason

The operator asked for saved works that can be redone and for a screen that needs no scrolling; a list with a faithful thumbnail answers "что мы выбрали, как она выглядит", a copy answers "переделать" without losing the first version (the operator picked it over redoing in place), and tabs in three columns put every tool within one viewport. Deleting stays possible but is guarded because it cannot be undone.

## Consequences

New routes GET /api/vector (list), GET /api/vector/{id}/thumb.png and POST /api/vector/{id}/copy; a new script vector-workspace.js and App.tabs in dialogs.js; the router switches the side menu off for a screen marked as workspace. The editor's picture and panel became columns of the frame (display:contents). Thumbnails use the geometry memo, so listing many works can evict the geometry of the work being edited (it is recomputed in about half a second). The AI tab names a missing library as the reason for a disabled button (ai.missing).
