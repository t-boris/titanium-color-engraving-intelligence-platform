## Context

Operator, 2026-10-19, after 0.9.0 listed the saved works: "Сделай возможность переименовать работу". A work is a plan row (name column, data_json with the history, undo and redo of the colour editor and the exports) and files; undo, history versions and "Вернуть эту версию" all belong to the document.

## Alternatives

1. A rename as a document operation in the history with undo (rejected: undo of a colouring would also undo a name, and every rename would add a document version)
2. A generic PATCH /api/plans/{id} for every plan kind (not asked for; other kinds name their plans differently)
3. A length cap and unique names (creation has none; a name made at creation could not be saved unchanged)

## Decision

POST /api/vector/{id}/rename with {name} changes the plan's name column and nothing else: no history entry, no document version, nothing on the undo or redo stack, "изменена" (derived from the history) and the thumbnail stay as they are, files exported earlier keep the name they were saved under and the next export and the made name of a copy use the new name. The name is stripped and must not be blank (the message is the one of creation, "give the plan a name"); there is no length cap and duplicates are allowed, as at creation. Naming a work as it is already named writes nothing; any other rename writes one audit row "vector_work_renamed" with the plan id, the old and the new name. The interface offers a pencil next to the name in the list of works, in the header of a work and on the long page of the other strategies; it opens a dialog with the name selected, Enter saves, a blank name is refused before any request.

## Reason

A name is a label of the work, not a state of its picture: putting it into the history would make undo and "Вернуть эту версию" rename the work, and a rename would change "изменена" and the thumbnail cache key for nothing. The audit row keeps a trace, as for copying and deleting a work.

## Consequences

New route and vector_job.rename_work; vector-workspace.js owns the dialog and the pencil (renameButton) used by vector.js; the plans list, plan screen and the export file name read the stored name, so they follow at once; exports already stored keep their old file name by design.
