## Context

Findings are derived again in every analysis run (after every accepted photo), so deleting a finding row would only last until the next run. The operator chose «скрыть, пока не изменится»: it comes back only when new data arrives for it.

## Alternatives

1. Hide forever by key (rejected by the operator: new data would never be seen)
2. Delete finding rows (they are recreated by the next run; earlier runs must stay unchanged)
3. Any change of the statement text reopens it (re-measuring shifts ids and decimals inside the text, so everything would reopen)

## Decision

The operator's mark is kept per finding key (`finding_mark`), not per run row. Hiding or acknowledging stores a snapshot of the finding's substance: kind, sub-kind, independent engravings, photographs, recipes and its ΔE (an observation's or a target's distance, else its recipe's expected error). The mark applies while the current finding matches the snapshot; a new engraving or photograph, a changed kind or sub-kind, or a ΔE that moved by 1.0 or more puts the finding back among «Требуют внимания» with the label «изменился». Pin and note persist regardless (a note is at most 2000 characters). «Вернуть» clears «учтено» or «скрыто». Earlier runs stay unchanged.

## Reason

Matches the operator's answer, survives recalculation and re-measurement, and a 1.0 ΔE threshold is about the smallest colour difference that is visible, so measurement noise does not reopen findings.

## Consequences

A new table `finding_mark`; every mark change is written to the audit; `findings_of` filters by the effective state.
