## Context

Re-measuring one photograph takes about 10–40 s (31 accepted photos: 12–20 min). Accepting the new measurement deletes the old photo and LightBurn files, so a database copy cannot undo it. Each accepted re-measure used to run a full analysis and the work reviews.

## Alternatives

1. One long request (no progress, lost when the page is left)
2. Database-only copy (cannot restore the deleted photo files)
3. Analysis after every photo (31 runs, and «new» would only compare with the previous photo)

## Decision

«Перепроверить все работы» is a background job, one at a time per workshop. It first makes a full workshop backup (`backup.make`: database and files); if the backup fails nothing changes. Then every accepted photograph is re-measured with `ingest.remeasure_pair` (the old measurement stays when the new one is not whole), the work review is recorded per replaced photo, and no analysis runs per photo. At the end, once: proposal statuses, one analysis run with the trigger `recheck`, and the works of each laser and lens touched. The job can be stopped between photos; the recalculation still runs for what was done. A report (per photo: replaced, kept with the reason, failed; the largest colour change; findings that appeared, disappeared or changed) is stored. While it runs, accepting, re-measuring and deleting a photograph are refused.

## Reason

Safe to undo, shows progress, and the findings before and after compare in one step.

## Consequences

New table `recheck_run`, routes `/api/recheck`; the backup needs free space about the size of the workshop (about 1.2 GB now).
