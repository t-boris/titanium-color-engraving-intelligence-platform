## Context

Observations are immutable (database triggers) and model_eligible is set once at acceptance. A re-measure replaces a photograph's pair by a revision (correction_of), so observation ids change; the stable anomaly key (findings-you-can-manage DEC-002) already follows correction_of to the first measurement.

## Alternatives

1. Flip observation.model_eligible: breaks immutability and is lost on a re-measure
2. Delete the photograph: removes every layer and the files, cannot be undone
3. Key by observation id: a re-measure brings the measurement back

## Decision

A table operator_exclusion holds the operator's exclusions; observations are never changed. «Убрать измерение» stores the original pair (following correction_of) and the layer index, so every later re-measure of the photograph stays out. «Вернуть» sets revoked_at; the record and the audit stay.

## Reason

Keeps the measurement history intact and the decision reversible, and survives «Перепроверить все работы» the same way hidden findings do.

## Consequences

One lookup resolves the current observation ids out (exclusions.excluded_ids). A re-photo of the same engraving is a different photograph and counts.
